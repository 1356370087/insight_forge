# Agent 面试业务亮点分析：研究压缩与质量门禁

## 一、业务亮点简述

多 Agent 深度研究存在三个典型问题：SubAgent 的完整检索历史会快速撑大主 Agent 上下文；原始搜索结果、模型推理和可引用证据混在一起，难以校验；低质量 SubAgent 结果如果直接汇总，会把错误继续传播到最终报告。

项目针对这些问题设计了"独立研究、分层留证、摘要交付、质量准入"的处理链路：

- 每个 Researcher 在独立上下文中完成一个聚焦研究主题，不继承完整 Supervisor 对话；
- 将搜索候选、抓取文档和主张级证据分层管理，只有通过安全准入的证据才能参与压缩；
- Researcher 默认向上层返回压缩摘要和指标，同步交付还会返回 Artifact 引用，核心检索产物持久化到任务级档案；
- 同步模式下摘要不足时，可按指定 Section、Offset 和长度限量回读经 SHA-256 校验的原始档案；
- 门禁开启后，使用可独立配置的评估模型审核工具结果和 SubAgent Handoff，未通过的交付不会写入共享研究状态。

这项亮点的核心不是简单"做一次摘要"，而是把 Agent 间传递的数据从无约束文本，升级为"摘要作为默认数据面、证据档案作为追溯面、质量门禁作为准入面"。



## 二、源码中的核心设计

### 1. Researcher 使用独立研究上下文

`ResearcherQueryEngine` 每次只用研究主题、可选记忆上下文和新的 `researcher_messages` 初始化状态。它不会把完整用户对话或 Supervisor 历史全部复制给 SubAgent。

这种设计带来两个直接收益：

- 不同研究方向互不污染，一个 SubAgent 的工具结果不会占用其他 SubAgent 的上下文；
- Researcher 可以把上下文预算集中在单一主题上，适合并发执行多个研究单元。



### 2. 检索信息按层次转化为可引用证据

| 层次 | 主要内容 | 作用 |
|---|---|---|
| 候选来源 | 搜索服务发现的 URL、标题、摘要、排名等 | 只表示"可能相关"，不能直接作为事实证据 |
| 抓取文档 | 最终 URL、正文、内容哈希、提取器、页码等 | 证明系统实际读取了什么内容 |
| 主张级证据 | Claim、原文摘录、文档与分块 ID、定位信息、来源权威度、置信度、安全状态 | 为报告中的结论提供可定位、可审核的证据 |
| 研究交付 | 压缩摘要、各类 Registry、研究迭代、质量结果和运行指标 | 用于 Agent 间交付、审计和恢复 |

搜索服务直接生成的综合性回答被明确标记为不可作为证据。进入压缩阶段时，代码还会排除 `quarantined`、`rejected` 和 `blocked` 状态的记录，避免未经准入的信息进入下游结论。



### 3. 压缩阶段只围绕证据进行综合

`compress_research()` 不会简单重放整个 Agent 对话，而是重新构造一份 evidence-only 输入，主要包含：

- 已通过安全准入的 Evidence Registry；
- 文档来源与内容标识；
- 受保护的工具结果；
- 当前研究主题。

`think_tool`、`ResearchComplete` 以及 Agent 的行动计划不会作为事实证据进入压缩输入。压缩摘要要求保留事实、日期、来源、短摘录、冲突和不确定性，并按照固定文本结构输出查询过程、研究结论和来源列表。

压缩模型最多尝试三次；遇到上下文超限会缩短证据输入，模型持续返回非法工具调用时，还可以从已准入的结构化证据生成确定性降级摘要。



### 4. 完整研究资料持久化为可校验 Artifact⭐

同步 Researcher 完成后，系统会把压缩摘要、Researcher 消息、原始证据输入、候选来源、抓取文档、Evidence Registry、研究迭代、评估结果和指标写入任务级 JSON Artifact。异步路径也会持久化压缩摘要、原始证据输入、各类 Registry、研究迭代和指标。

Artifact 使用原子写入并生成 SHA-256。再次读取时，代码会同时校验任务 ID、路径边界和内容哈希，防止读取错误任务或使用已被篡改的档案。

正常情况下，`ConductResearch` 返回给 Supervisor 的主要内容只有压缩摘要、Artifact 引用和指标，不会把完整检索历史直接灌入模型消息窗口。已验收的原始证据仍保留在共享状态和持久化档案中，供报告生成、质量评估和恢复流程使用。



### 5. 支持按需、限量回读原始证据⭐

同步研究模式提供 `ReadResearchArtifact` 工具。Supervisor 必须提供任务 ID 和 Artifact SHA-256，并指定要读取的 Section、Offset 与 `max_chars`。

单次默认最多返回 12,000 字符，硬上限为 30,000 字符，并通过 Offset 分页。

**Supervisor 提示词要求优先使用压缩摘要，只有在处理具体证据缺口、来源冲突或缺失引用时，才读取最小必要片段**。

如果一份 Handoff 先前被质量门禁拒绝，Supervisor 读取其 SHA 校验后的证据片段还会触发重新评估；只有复核通过后，Artifact 才会重新进入共享研究状态。



### 6. 工具结果评审与 Handoff 准入是两道不同门禁⭐

第一道门禁位于 Researcher 内部。评估模型从**相关性、来源质量、证据覆盖和交叉印证**四个维度审核本轮工具结果，并返回 `continue`、`retry` 或 `complete`。结果不足时，缺口和建议查询会反馈给 Researcher，推动继续补证据。

第二道门禁位于 Supervisor 接收 SubAgent 结果之前。评估模型从相关性、来源质量、证据覆盖和 Groundedness 四个维度判断 Handoff 是否可以接收，同时结合非空内容、可追踪来源数量等确定性检查。

质量评估开启后：

- 同步模式下，被拒绝的 Handoff 只向 Supervisor 返回拒绝状态、Artifact 引用和具体缺口，其原始笔记与证据不会合并进共享状态；
- 异步模式下，只有 `accepted_outputs` 会进入 `completed_task_outputs` 和各类 Registry；
- 如果研究已经执行但最终没有任何已准入证据，报告生成阶段会阻止正常报告产出；
- 被拒绝的完整 Handoff 仍会保留为 Artifact；同步路径支持重新评估，具备有效 Artifact 引用时，终止恢复流程也可以只使用其中通过安全准入的证据生成明确标注的部分结果。

因此，真正阻断低质量信息跨 Agent 传播的是 Handoff 准入；工具结果评审主要负责控制 Researcher 是否继续补充研究。



### 7. 面试时必须说明的能力边界

运行时质量评估由 `quality_evaluation_enabled` 控制，当前源码默认值是关闭。

开启后，评估器异常时默认采用 `fail-open`，但最小来源数、空结果和全量工具失败等确定性检查仍然生效。如果业务要求严格阻断，应在目标部署中显式开启质量评估，并根据风险将评估失败策略调整为 `fail-closed`。

当前默认的 `balanced` 严格度要求四个质量维度单项不低于 3 分且平均分不低于 3 分，并默认要求至少两个可追踪来源。阈值可以按场景切换为更宽松或更严格的策略。

另外，显式的 `ReadResearchArtifact` 目前属于同步 Supervisor 工具集；异步路径虽然同样持久化 Artifact 并执行 Handoff 准入，但没有完全相同的交互式回读与重新准入工具入口。



## 三、面试时的一分钟介绍⭐

我主要解决的是多 Agent 研究过程中**上下文膨胀**、**证据不可追溯以及低质量结果级联传播**的问题。

每个 Researcher 使用独立上下文完成单一主题研究，检索结果依次沉淀为候选来源、抓取文档和主张级证据。Researcher 结束后只向 Supervisor 返回保留来源、冲突和不确定性的压缩摘要，核心检索产物则持久化成带 SHA-256 的任务 Artifact；

同步模式下摘要不足时，可以按 Section 和 Offset 限量回读。质量上又设置了两道评审：Researcher 内部审核工具结果是否需要继续补证据，Supervisor 在接收 Handoff 前再次审核相关性、来源、证据覆盖和 Groundedness。门禁开启后，被拒绝的结果不会进入共享状态，而是保留档案和失败原因，支持补充研究或重新评估。



## 四、面试官可能提问及参考回答

### 问题 1：为什么要给每个 Researcher 独立上下文？

不同研究方向需要的证据不同。如果所有 SubAgent 共用完整对话，既浪费 Token，也容易把其他任务的工具结果和错误结论带入当前研究。独立上下文让每个 Researcher 只围绕一个自洽主题工作，上层再通过标准 Handoff 汇总结果。



### 问题 2：分层证据机制具体解决了什么问题？

它把"搜索到一个链接"、"成功读取一份文档"和"某个结论被原文支持"区分开。候选来源不能直接当证据，必须先抓取并形成带内容哈希的文档，再提取带原文摘录和定位信息的主张级证据，这样才能追踪结论来自哪里。



### 问题 3：压缩会不会丢失重要信息？⭐

压缩输入不是简单截取聊天记录，而是由已准入证据、文档信息和受保护工具结果重新构造，并要求保留来源、日期、冲突和不确定性。即使摘要仍然遗漏细节，Artifact 也不会被删除；同步 Supervisor 可以针对具体缺口限量回读，异步档案则保留给审计和任务恢复流程。



### 问题 4：为什么不把所有原始资料直接交给主 Agent？

完整搜索历史通常包含重复网页、工具错误、行动计划和潜在提示注入内容，会显著增加 Token 和噪声。默认传递摘要可以控制上下文规模；原始证据通过 Artifact 留在旁路，同步路径需要时再精确读取，实现"默认轻量、必要时可追溯"。



### 问题 5：Artifact 为什么需要 SHA-256？

Artifact 引用和文件内容必须建立稳定绑定。读取时重新计算哈希，可以发现文件缺失、任务引用错误或内容被修改，避免 Supervisor 基于与原始 Handoff 不一致的证据进行复核。SHA-256解决的是完整性校验，不等同于访问控制或数字签名。



### 问题 6：工具结果门禁与 SubAgent Handoff 门禁有什么区别？⭐

工具结果门禁发生在 Researcher 内部，用来决定继续、重试还是结束研究；

Handoff 门禁发生在 Agent 边界，决定整份研究交付能否进入 Supervisor 共享状态。前者负责过程纠偏，后者才是阻止低质量信息跨 Agent 传播的核心准入点。



### 问题 7：Handoff 被拒绝后如何处理？⭐

系统不会把其摘要、原始笔记和证据直接合并到共享状态，而是保留**拒绝原因、缺失信息和后续任务建议**。同步路径还会向 Supervisor 提供 Artifact 引用，可读取经哈希校验的最小证据片段触发复核；

异步任务则保留持久化档案和准入状态。这样既不传播低质量结论，也不会丢失可恢复的研究成本。



### 问题 8：如何避免 LLM 评估模型本身误判？

评估模型必须返回结构化 JSON，代码会校验"评分、接受状态和缺口说明"是否自洽，矛盾时允许一次协议修复。

除此之外还有确定性检查，例如非空证据、工具失败数量和可追踪来源数；LLM 即使给出高分，只要硬检查不通过，结果仍会被改为重试或拒绝。



### 问题 9：评估模型不可用时系统怎么办？⭐

这是可配置的工程取舍。当前默认是语义评估 `fail-open`，避免外部 Judge 故障拖垮研究任务，但确定性证据检查仍会执行；高风险场景可以设置为 `fail-closed`，评估器失败时停止继续消耗研究预算，并拒绝 Handoff，等待后续复核。



### 问题 10：这套设计如何体现业务价值？⭐

它同时控制了成本和质量：摘要交付减少主 Agent 上下文负担，Artifact 降低问题追查和重复研究成本，Handoff 门禁减少错误在多个 Agent 之间放大。实际评估时可以观察摘要与原文字符比、Artifact 回读率、Handoff 拒绝率、补充研究次数、证据覆盖率以及最终报告返工率。



### 问题 11：这套机制还有哪些局限？

质量评估会增加一次或多次模型调用及延迟，超长证据还会受到评估输入上限影响；SHA-256只能证明内容未变化，不能证明来源本身真实；默认关闭和 `fail-open` 也意味着部署配置会直接影响门禁强度。因此生产环境需要固定质量策略、记录评估模型与阈值，并结合人工抽检持续校准。
