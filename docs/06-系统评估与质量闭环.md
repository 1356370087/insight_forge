# Agent 面试业务亮点分析：系统评估与质量闭环

## 一、业务亮点简述

深度研究 Agent 的难点不只是"能不能生成报告"，而是如何稳定判断报告是否真正可靠。单看任务是否成功或一个综合分，容易出现报告写得完整、结构清晰，但关键结论缺少证据、引用不准确或来源权威性不足的问题。

针对这个问题，项目建立了一套可重复运行的质量闭环：

- 打通本地评估和 LangSmith 数据集批量评测，复用核心评估器；
- 使用 LLM-as-Judge 从 6 类、13 项指标评价研究报告；
- 对证据、引用、来源和需求覆盖度设置非补偿式门禁，避免优势指标掩盖关键短板；
- 将报告、评估结果和运行 Journal 持久化，支持不重跑研究过程、只独立重跑 Judge；
- 通过评估结果定位问题，为来源筛选、证据核验和需求覆盖检查提供明确的改进方向。

这项工作的核心价值，是把 Agent 质量从"主观感觉不错"变成"可量化、可做门禁判定、可复现、可持续改进"。当前代码会输出是否通过及失败原因，真正阻断交付还需要上层流程消费这个判定字段。



## 二、源码中的核心设计

### 1. 本地评估与 LangSmith 批量评测共享核心评估器

`tests/run_evaluate.py` 使用 LangSmith 的数据集和 `aevaluate` 执行批量实验，同时记录模型、搜索工具和并发参数等元数据，适合做版本对比和回归评测。

`tests/run_local_evaluate.py` 提供本地评估入口，每次研究使用独立运行标识并关闭记忆污染，输出单题和汇总级 JSON、Markdown 结果。它更适合在开发阶段快速调试评分规则、检查单个失败案例。

两条链路共用 `tests/evaluators.py` 中的核心评估器，避免基础评价标准发生漂移。LangSmith 链路在数据集有参考答案时还会执行正确性评估；综合分、一致性校准和非补偿式门禁则由本地评估入口负责。



### 2. 6 类、13 项 LLM-as-Judge 指标⭐

| 评估类别 | 核心指标 | 数量 | 综合分与门禁口径 |
|---|---|:--:|---|
| <strong>综合质量</strong> | 研究深度、来源质量、分析严谨性、实用价值、平衡与客观性、写作质量 | 6 | 均进入综合分；来源质量同时属于门禁 |
| <strong>相关性</strong> | 是否围绕用户问题作答 | 1 | 进入综合分 |
| <strong>结构性</strong> | 结构与逻辑衔接 | 1 | 进入综合分 |
| <strong>证据完整性</strong> | 证据支撑度、引用准确性、来源权威性 | 3 | 前两项进入综合分；三项均属于门禁 |
| <strong>需求覆盖度</strong> | 用户要求和研究维度的覆盖情况 | 1 | 进入综合分和门禁 |
| <strong>工具效率</strong> | 工具选择与调用效率 | 1 | 进入综合分 |

证据类指标不是由多个互相独立的 Judge 重复判断，而是先生成同一份"主张清单"，再从中计算证据支撑度、引用准确性和来源权威性，降低不同评分之间相互矛盾的概率。

本地评估还增加了确定性的 `judge_consistency_score`。当报告级来源质量明显高于逐条主张审计得到的来源权威性时，代码会保守地下调来源质量。为避免来源质量被重复计算，来源权威性保留为门禁项但不进入均值；一致性分进入均值，所以本地综合分仍由 13 个维度组成，但它与上表的 13 个基础 Judge 指标不是完全相同的一组。

事实正确性和参考答案正确性是额外的兼容字段，不计入上述 13 项。本地数据没有独立真值或标准答案时，它们会标记为 `not_scored`，而不是让 Judge 凭同一批材料自行证明结论正确。这体现了对评估边界的控制。



### 3. 非补偿式质量门禁⭐

普通加权平均存在一个问题：相关性、结构和写作得分很高时，可能抵消证据质量较差的问题。项目因此将以下六项指标设为关键门禁：

- 来源质量与来源权威性；
- 证据支撑度与引用准确性；
- 需求覆盖完整性；
- Judge 一致性。

当前规则要求：综合分达到 0.75 且所有关键指标不低于 0.70，才能达到 `good` 并通过；综合分达到 0.85 且所有关键指标不低于 0.80，才能达到 `excellent`。

任一关键项低于 0.70 都会导致门禁不通过；关键项缺失、评估器报错或低于 0.50 时，质量等级直接记为 `failed`。

因此，"内容好读但证据不可靠"的报告会被明确判定为门禁未通过，而不会仅凭平均分被标记为合格。



### 4. 基于持久化结果独立重评

本地评估支持两种低成本重评方式：

- `--rescore-json`：读取已有研究结果，重新执行 Judge 并更新综合分、门禁结果和 Markdown 报告；
- `--refresh-quality-json`：不调用 Judge，也不重算综合分，只根据已有综合分和指标刷新质量等级与门禁结果。

重评必须先有包含问题和最终报告的结果 JSON。如果 JSON 缺少部分评估状态，还可以通过运行标识，从 `.runs/<run_id>/context/session_memory.jsonl` 中补充恢复 Journal 里实际存在的研究摘要、原始笔记、覆盖清单或证据注册表；Journal 不能替代结果 JSON，也不保证每次运行都包含全部字段。

所以简历中的"基于事件日志独立重跑评估"，更准确的面试表述是：以已持久化的结果 JSON 为主体，按需用 QueryEngine 的 JSONL 运行 Journal 补充评估状态，只重跑评估阶段，不重新执行成本较高的研究流程。



## 三、面试时的一分钟介绍

我主要解决的是深度研究 Agent 报告生成了，但质量无法稳定判断的问题。

我把本地单次评估和 LangSmith 数据集批量评测打通，共用 6 类、13 项核心 LLM-as-Judge 指标，覆盖内容质量、相关性、结构、证据、需求覆盖和工具效率。与普通平均分不同，我对六项关键指标设置了非补偿式门禁，因此其他指标再高也不能掩盖证据缺陷。

同时，我把研究结果和 JSONL 运行 Journal 持久化，使评分规则调整后可以只重跑 Judge，不需要重新执行整条研究链路。



## 四、面试官可能提问及参考回答

### 问题 1：为什么选择 LLM-as-Judge，而不是只用传统自动指标？

深度研究报告是长文本，既要判断是否回答了问题，也要判断分析是否严谨、证据是否支撑结论、建议是否可执行。字符串匹配或相似度指标很难覆盖这些语义维度。LLM-as-Judge 更适合做规模化初筛，但它不是事实真值，所以项目同时使用结构化评分标准、确定性一致性规则、证据门禁，并为后续黄金集和人工校准保留接口。



### 问题 2：6 类、13 项指标具体如何划分？

综合质量包含 6 项：**研究深度**、**来源质量**、**分析严谨性**、**实用价值**、**平衡客观性**和**写作质量**；再加**相关性**、**结构性**各 1 项；证据完整性包含证据支撑度、引用准确性和来源权威性 3 项；最后是需求覆盖度和工具效率各 1 项，共 13 项。



### 问题 3：为什么不能只看综合分？

因为平均分具有补偿性。例如报告写作和结构都很好，可能把来源质量较差的问题平均掉，但对于研究 Agent 来说，缺少证据的核心结论属于不可接受风险。因此综合分用于排序和观察整体趋势，关键指标门禁用于输出是否通过的判定，两者职责不同。当前实现生成门禁字段和失败原因，是否进一步阻断交付由上层流程决定。



### 问题 4：非补偿式门禁是如何工作的？⭐

代码先计算综合分，再单独检查来源质量、来源权威性、证据支撑度、引用准确性、需求覆盖度和 Judge 一致性。达到 `good` 需要综合分至少 0.75，并且所有关键项至少 0.70；达到 `excellent` 需要综合分至少 0.85，并且所有关键项至少 0.80。只要关键项不达标，就不能依赖其他高分补偿。



### 问题 5：本地评估和 LangSmith 评测分别解决什么问题？

本地评估主要服务开发调试，可以快速查看单题评分、失败原因和中间证据，并生成 JSON、Markdown 产物。LangSmith 主要服务数据集级批量评测、不同模型或配置的实验对比，以及运行元数据和轨迹管理。两者复用核心评估器；本地额外负责综合分、一致性校准和门禁，LangSmith 在有参考答案时可增加正确性评估。



### 问题 6：如何降低不同 Judge 之间评分矛盾的问题？

首先，证据相关指标共享一份主张级审计清单，不让多个 Judge 各自理解一遍报告。其次，加入确定性一致性校准，例如来源质量明显高于逐条来源权威性时，保守地下调来源质量。最后，没有独立真值时不强行评分事实正确性，而是明确标记为未评分。



### 问题 7：为什么可以不重跑研究，只重跑评估？

重评首先从结果 JSON 读取问题和最终报告；如果部分状态已写入 QueryEngine 的 JSONL 运行 Journal，还可以按运行标识补充恢复。随后重新调用评估器并计算综合分与门禁。这样修改 Judge 提示词或评分规则时，不需要再次支付研究阶段的搜索和模型推理成本，但 Journal 只是补充来源，不保证能单独重建全部评估输入。



### 问题 8：下一步如何形成真正的质量闭环？⭐

质量闭环要区分两类改动。修改 Judge 提示词、指标或门禁时，可以对同一份持久化结果独立重评，隔离评估规则本身的变化；修改检索、来源筛选或报告生成逻辑时，必须在固定问题集上重新运行研究，再比较评分和门禁，不能用未变化的旧报告证明上游改动有效。

下一步重点是为量化主张绑定一手来源、对高风险数字做交叉验证，并在生成前检查需求覆盖清单。



### 问题 9：这套评估体系还有哪些局限？⭐

第一，没有独立标准答案时，LLM Judge 只能判断"报告是否被现有证据支撑"，不能等价于外部世界中的事实正确性。第二，当前最终状态没有保留所有 Researcher 级工具名称，因此工具效率只能基于可观察轨迹评分。生产化时还需要建设人工标注黄金集，定期校准 Judge，并监控不同模型版本带来的评分漂移。
